# WordPress v19 acceptance testing

`tests/v19.sh` is the release acceptance flow for this appliance. It expects
the standard TurnKey harness password and result environment variables.

The test covers:

- successful firstboot and active Apache/MariaDB services;
- invalid, no-scheme, explicit HTTP, and explicit HTTPS domain handling;
- administrator login and dashboard access;
- creation and persistence of a published post and authenticated session across
  an Apache/MariaDB restart;
- valid official update metadata without changing the installed version;
- official WordPress core checksum verification and the root-only updater guard;
- root ownership of core/config, the documented writable `wp-content`
  directories, and `wp-config.php` mode `root:www-data 0640` after salt rotation;
- absence of the appliance password and generated WordPress salts from the
  firstboot log.

The build separately verifies the exact WordPress 7.1 archive SHA-256 before
extraction and then verifies the extracted files against WordPress.org's
per-file checksum manifest.

The Docker acceptance environment does not validate installer, kernel, or
hardware behavior. Its hostname and sysctl limitations are harness-level and do
not relax any application assertion above.
